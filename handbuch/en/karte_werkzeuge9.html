Map editor: test in game and more tools

Start the game with the current map at the press of a button, and turn models from Blender and other games into brushes.

Test in game#

Build > Test in game lists the engine from the preferences and every game program found in the engine folder: Jedi Academy SP/MP, OpenJK, Movie Duels and, for Jedi Outcast maps, Jedi Outcast SP/MP and OpenJO. A click starts the chosen program with the current map (+devmap). The choice is remembered.

  • Which .bsp: the quick bake of the current map if it is up to date (Quick bake), otherwise a .bsp that is newer than the saved, unchanged map, otherwise the program builds first with the first [Test] entry of the Build menu and starts the game when the build is done.
  • Where it goes: the .bsp is packed as zzz_jkstudio_test.pk3 into the folder spieltest next to the program settings - never into the game folder. The game learns about the folder from a start parameter: fs_cdpath (all engines of this family; your game settings stay as they are) or, if the game already has a map with the same name, fs_homepath (Jedi Academy MP, Jedi Outcast MP, OpenJK, Movie Duels), because that folder takes precedence. Which parameter a program knows is read from its .exe.
  • Only if neither works (for example Jedi Academy SP with a map name the game already has), the program asks before it writes the archive into the game: into a mod folder jkstudio_test (started with +set fs_game jkstudio_test), or into the folder of the active mod. You can delete the file later.
  • The console shows the way that was chosen and the whole command line. Map names with spaces cannot be loaded with devmap; save the map under a name without spaces.
Not in NetRadiant-Custom. NetRadiant-Custom's own Run Engine After Compile (preferences, page Build) stays as it is: it starts the engine from the game folder after every build.

Geometry to brushes#

File > Import geometry as brushes reads a model (.obj, .fbx, .glb or .gltf, for example from Blender) and turns it into brushes. A window lists the parts of the file; for each part choose Auto, Brushes or Model + clip - the column Preview shows at once how many brushes it becomes and whether they are detail. Insert inserts everything as one undo step and selects it; then the optimizer opens.

  • Closed parts are split into convex brushes (a BSP over the faces of the model, like q3map2 builds one). Faces that lie in one plane become one brush side. Sides on the surface of the model get its material as shader (Shader prefix + material name) and its UV as texture alignment; sides inside the model, which nobody sees, get caulk.
  • Open parts (single surfaces, decoration) become thin brushes behind each flat face; small and open parts become detail, so they do not cut the map into BSP leaves.
  • Model + clip keeps the part as a model: it is written as .obj into the program's import folder (next to the settings, never into the game), a misc_model points to it, and clip brushes from the same decomposition make it solid. The editor and q3map2 (-fs_pakpath) search this folder. Auto takes brushes for closed parts with at most 256 brushes, otherwise model + clip.
  • Scale and Y up (Blender, glTF) to Z up: Blender and glTF use Y as up, the game Z; one Blender metre is one unit unless you scale it. A .bsp of another id Tech 3 game (Quake III, Elite Force, Return to Castle Wolfenstein, Enemy Territory, Warsow) opens like Open .bsp, with the reader of that game.

Drag a model into the map#

Drag an .obj, .fbx, .glb or .gltf file from the Explorer onto the map editor. The program converts it to an MD3 with its own shader and copies the textures (embedded in the file or next to it); all of it goes into the import folder next to the settings, never into the game. A misc_model appears under the mouse pointer in the 2D view (or in front of the camera) and is selected; one undo removes it. Models larger than 511 units are scaled down in the MD3 and get modelscale.

Test in game and Pack map as .pk3 pack the import folder into their archive, so the game finds the models, shaders and textures.

Check jumps and space#

View > Map tools (JK Studio) > Check jumps and space > Check (selection or around the camera) checks the selection (or 512 units around the camera) with the movement of the game: where the player can stand (green crosses) or fits only crouched (yellow), and from which edges a running jump lands on another floor - blue for a normal jump, purple where only the force jump of the chosen level gets there. It runs in the background; Clear removes the display.

  • The movement is the port of the game code: running speed 250, gravity 800, jump 225, the player box 32 x 32 x 64 (crouched 40), steps up to 18 units, floors up to 45 degrees. The force jump follows the game: holding the jump key it rises up to 96, 192 or 384 units (levels 1 to 3); letting go earlier jumps lower. Jedi Outcast and Movie Duels compute it the same way.
  • The chosen force jump level also applies to Play in editor (F6): hold the space bar to jump higher.

NPC paths#

View > Map tools (JK Studio) > NPC paths > Show waypoint network shows the network the game builds from the waypoints when it loads the map - connections turquoise, jump connections orange. The game builds a network only from more than three waypoints; the console says so. Test walk (first to last selected entity): select two entities (for example two waypoints, or an info_player_start and a waypoint) - an NPC walks from the first to the last one with the game's path finding and movement; the path is yellow and a box walks along it in real time. The console says after how many seconds it arrives, or where it gets stuck. Run switches between running and walking.

Linked copies#

Select brushes and patches (for example a pillar or a lamp) and choose View > Map tools (JK Studio) > Linked copies > Make linked copy of selection: they become a linked group, and a copy appears next to it. Select the copy and repeat for more copies. From now on, whatever you change in one copy - add, delete, resize or retexture brushes - happens in all of them in the same step; one undo takes it back everywhere. Moving a whole copy moves only that copy. Unlink selected group makes a copy independent again.

The copies are func_groups with the keys _bhed_link and _bhed_link_origin; the game and q3map2 treat them like any func_group. Copies are moved, not rotated.

Curve tool#

Place a few point entities (for example info_null) along the course you want and select them in that order. View > Map tools (JK Studio) > Curve tool lays a smooth curve through them and builds, as one undo step: Path (patch) (a flat strip, 128 wide), Pipe (patch), Railing (patches) (a rail on each side at hand height), Bridge (patches) (deck with sides and underside), Path corners (func_train, camera track) (a chain of path_corner linked by targetname/target - for func_train or a camera track) or NPC waypoints (a linked chain of waypoints). Patches get the texture selected in the texture browser; the spacing follows the grid.

Scatter models#

Place one misc_model_static (or misc_model) as the template - for example a rock or a crate - and select it together with the brushes of the area (for example the floor). View > Map tools (JK Studio) > Scatter models puts 10, 25 or 50 copies onto the walkable surfaces in that area, with random angle and scale, at least 48 units apart, as one undo step. Without brushes it uses 256 units around the template.

Every misc_model_static becomes a static object of the game, and Jedi Academy and Movie Duels stop with an error after 2000 (MAX_MISC_ENTS). Scattering stops at that limit, and the optimizer counts misc_model_static against it. Jedi Outcast has no misc_model_static; there the copies are misc_model.

Terrain sculpt#

Make a terrain of patches (for example a big patch with many rows, or the patches of the terrain generator). View > Map tools (JK Studio) > Terrain sculpt > Sculpt with the left mouse button (camera): now the left mouse button in the camera shapes the patches under the pointer instead of selecting - hold it and move. Choose Raise, Lower, Smooth or Flatten (to the height where you pressed) and a radius of 64, 128 or 256; the effect fades towards the edge of the circle. One stroke is one undo step.

Only patches are shaped; terrain brushes keep their shape. Blending textures on the terrain (alpha maps) is not part of this version yet.

Asset browser#

View > Map tools (JK Studio) > Asset browser opens a window with the models (.md3, .glm, .ase, .obj), the prefabs and the sounds of the game, each with a preview: the texture of a model, the waveform of a sound, the outline of a prefab from above. Search narrows the list - every word must appear in the path. Drag an entry onto a 2D view or the camera: a model becomes a misc_model, a sound a target_speaker, a prefab is inserted - at the place under the pointer. A double-click puts it in front of the camera. Everything is one undo step.

Prefabs are .map files in the import folder (import/prefabs in the settings folder). Select brushes and entities, enter a name under Prefabs and click Save selection as prefab. Build > Pack map as .pk3 takes the import folder along. The asset browser is not in NetRadiant-Custom.

To Blender and back#

Select brushes and choose File > Export selection for Blender (.glb/.obj): they are written as .glb (or .obj) with Y up, the way Blender expects, one object per brush, the shader names as materials. Edit the part in Blender and export it again as .glb or .obj with the default settings. File > Import geometry as brushes with Y up (Blender, glTF) to Z up switched on (the default) brings it back to the same place in the map.

Restore after a crash#

The map editor saves automatically like NetRadiant-Custom (preferences, page Autosave: <map>.autosave.map next to the map). If the program did not close properly - a crash, a power cut - the editor notices it at the next start and asks whether to load the autosave, when it is newer than the map. The restored map keeps its name and counts as changed: save it to keep it. Answer no, and the last map opens as usual.
